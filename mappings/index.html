DIO/ODI Application Mappings

Application Mappings are derived analytical layers that project concepts from the canonical DIO/ODI Reference Vocabulary into external technical or conceptual domains.

Boundary: mappings do not modify the Reference Vocabulary, add canonical concept definitions, or imply that the external framework and DIO/ODI are equivalent. They make explicit, reviewable analytical relations between distinct conceptual systems.

DIO Reconstruction Failure Modes × RAG Pipeline

Maps current DIO Reconstruction Failure Modes to generic retrieval-augmented generation pipeline loci, mechanisms, observable symptoms, and hypothetical incidents. The live page also documents iterative and hypothesis-conditioned evidence acquisition as a later extension connected to the Commit-Boundary research trajectory.

Status: base mapping introduced and archived in Reference Model v0.2.0; retained in subsequent archived v0.3.x releases. The iterative/hypothesis-conditioned extension was added 25 October 2026, first included in archived v0.4.0, and carried forward in archived v0.5.0 and archived v0.6.0; carried forward in archived v0.7.0 and v0.8.0; current archived v0.9.0.

HEM Heterogeneity Taxonomy × DIO Reconstruction Consequences

Uses the Heterogeneous Entity Matching taxonomy as an external axis for examining how heterogeneous input conditions may contribute to DIO reconstruction failures or increase Semantic Vulnerability. Available as a human-readable frontend, Markdown source, JSON-LD, Turtle RDF, and SVG conceptual bridge.

Status: introduced in v0.3.0; included in v0.3.2 and carried forward in archived v0.4.0 and archived v0.5.0 and archived v0.6.0; carried forward in archived v0.7.0 and v0.8.0; current archived v0.9.0 · HEM source: 10.1016/j.datak.2026.102575

DIO/ODI Commit-Boundary Contract × Policy-as-Code Authorization

Maps DIO/ODI-informed commit-boundary obligations to Policy-as-Code capabilities and residual integration requirements, using OPA/Rego and Cedar as documented technical reference points. It distinguishes policy decisions from evidence validation, enforcement, and atomic graph commitment.

Status: added to the source tree on 25 October 2026, included in archived Reference Model v0.4.0, and carried forward in archived Reference Model v0.5.0 — v0.5.0 DOI and archived Reference Model v0.6.0 — v0.6.0 DOI; carried forward in archived Reference Model v0.7.0 and v0.8.0; current archived Reference Model v0.9.0 — v0.9.0 DOI. The mapping does not modify the canonical Reference Vocabulary.

DIO/ODI-Informed Agentic ER Commit-Boundary Architecture

Reconstructs the internal architecture relations connecting selected DIO/ODI diagnostics, domain-governed identity-preserving constraints, mutation-specific propositions, claim-specific evidence eligibility, two-phase authorization, and the conditional commit invariant. Includes a machine-readable relation graph and an architecture diagram.

Status: live mapping version 0.3.1, a provenance-only synchronization to public arXiv v2 (5 November 2026). Section-level anchors follow production manuscript v55 dated 4 November 2026. Version 0.3.0 remains the mapping included in archived Reference Model v0.6.0. The mapping is non-normative, contains 120 local architecture concepts and 206 qualified relation assertions, and does not modify the canonical Reference Vocabulary.

Architecture
