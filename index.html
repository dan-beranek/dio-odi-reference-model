What belongs where

Reference Model
The versioned research-software package and live source repository. An archived release captures a package state; it is not identical to the maintained website or the entire publication corpus.
Reference Vocabulary
The canonical SKOS ConceptScheme identified by its persistent URI. It is a component of the Reference Model, not a separately archived work with its own version-specific Zenodo DOI.
Application Mappings
Derived, non-normative analytical projections. They reuse canonical identifiers but do not add or alter canonical concept definitions or relations.
Corpus Metadata Registry
An operational metadata layer for works, versions, relations, references, distributions, and keywords. It supports provenance and navigation but does not modify the Reference Vocabulary.
Semantic Change Feed
A curated, append-only history of documented semantic and provenance-relevant changes across the reference system. It records transitions and preserved invariants without replacing any component source of truth.
DIO/ODI Hub
The project-level entry point for the Manifest, publications, research context, and updates: danielberanek.cz/manifest-dio/.

Machine-readable access

For automated discovery and reuse, use canonical representations and operational metadata rather than scraping this overview page.

  • llms.txt — structured orientation to repository resources.
  • metadata.json — compact release and component summary.
  • Semantic Change Feed events and JSON Schema — documented semantic history and validation contract.
  • SKOS/RDF Turtle · JSON-LD · DCAT 3.
  • GitHub source repository — versioned source files, validation, and release history.

The wider DIO/ODI research corpus
