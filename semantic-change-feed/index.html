Record structure and governance

01 · Change

Previous and resulting state

Every event describes the documented transition without inventing a precise diff where the source does not provide one.

02 · Preservation

Preserved invariants

Records explicitly state what remains stable: identity, URI continuity, hierarchy, relations, or a mapping boundary.

03 · Evidence

Provenance and temporal basis

Primary publications, release notes, registries, and archival records are distinguished. A publication date is not silently treated as an edit timestamp.

04 · Lineage

Change relations

Events can be related, superseded, or corrected. Published identifiers are not silently rewritten.

Machine-readable access

Use the JSON feed for automated processing and the JSON Schema to validate event records. The initial historical register is selective: it covers documented events, not every repository change since the project began.
